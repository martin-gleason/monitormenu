# F2 — Name your monitors

Created: 2026-10-20 07:30 -05:00 · Edited: 2026-10-20 07:30 -05:00

**Status:** draft, at the gate (`O13`) · **Milestone:** v1.0 · **Owner:** agent · **Delivers:** FR10

Learning level 5%, locked (`O2`); every task is `owner: agent`.

## What the user gets

"DELL G3223D" becomes "Desk" (or "Left", or "Omen"). Pick Rename… under a monitor in the menu, type a name, and that name is what the menu, the switcher, Siri, Shortcuts, the URL scheme and `monitorctl` all use from then on. The monitor's own name stays visible in smaller type so nothing is hidden. Names survive relaunches and follow the monitor by its serial number, so unplugging and replugging, or a second monitor of the same model, cannot mix them up.

## Requirement (proposed delta D13; the spec is not edited by the agent)

**FR10** — A monitor can be given a name of the user's choosing from the menu. The name is shown everywhere the monitor is named, matches `--display`, `?display=` and the Monitor parameter of every intent, persists across launches, is keyed by the monitor's serial, and can be cleared to return to the monitor's own name.

### F2-T1 — Name store and resolution in MonitorCore

Owner: agent · Delivers nothing user-visible (foundational) · `MonitorNames`: a `[serial: name]` map in `UserDefaults` (suite `dev.marty.MonitorMenu`, shared with `monitorctl`), `displayName(for:)`, `set`, `clear`; `Monitor.displayName`. Checkpoint: `swift test` round-trips a name through a scratch defaults suite; M7 (key by display id instead of serial) seen red then green.

### F2-T2 — Rename… in the menu, names everywhere in the app

Owner: agent · Delivers FR10 · A Rename… item under each monitor opens a small sheet-less panel (NSAlert with a text field; empty clears). Menu header, switcher rows, `Actions.resolve` and the intents' Monitor parameter use the display name; the monitor's own name shows as the header's tooltip and in the switcher's section line. Checkpoint: rename the Dell to "Desk", quit and relaunch, menu says Desk; `open "monitormenu://pip/off?display=desk"` resolves.

### F2-T3 — `monitorctl rename` and `list` show both names

Owner: agent · Delivers FR10 · `monitorctl rename <display> "<name>"`, `monitorctl rename <display> --clear`; `list` prints `Desk (DELL G3223D)`. Checkpoint: rename from the CLI, open the menu, the menu agrees without a relaunch (the app re-reads names on menu open).

## Design notes (for the reviewer, not binding)

- Storage is `UserDefaults`, not a file: one small dictionary, no secrets, and both processes already share the suite. A monitor with no alphanumeric serial is keyed `vendor-model-serial`, the same key the store already uses.
- The rename UI is an `NSAlert` with an accessory text field rather than a window: one line of state, no window controller, and it works from a menu bar app without activating a main window.
- No change to `SwitchCore`'s whitelist or DDC paths; this feature never writes to the monitor.
