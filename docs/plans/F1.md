## What the user gets

A menu bar icon. Open it and every DDC-capable monitor is listed with its inputs; click one and the monitor switches. Brightness, contrast, standby and (on monitors that have it) picture-in-picture sit under the same menu. A hotkey opens the same input list without the mouse. Its actions show up in the Shortcuts app and Siri the first time it runs, and a URL scheme or `monitorctl` lets Alfred, Raycast or a script do any of it.

## Design notes (for the reviewer, not binding)

- Display matching: `IOAVService` instances are found under `DCPAVServiceProxy` with location `External`; each is matched to a `CGDisplayID` through the EDID serial and product id in the IORegistry. Only matched, answering services are listed (FR1, D4).
- Every I2C transaction runs on a serial queue off the main thread with a 250 ms timeout and up to three retries, measured in F1-T1 against RR2 (NFR4).
- The capabilities string is parsed once per display and cached until the display set changes. The parser is pure Swift and tested against the captured G3223D string (M2).
- Reads use the DDC "Get VCP Feature" reply; the current value is the low byte for inputs (M3) and the 16-bit value for brightness and contrast.
- Input names come from the MCCS table (0x0F DisplayPort 1, 0x10 DisplayPort 2, 0x11 HDMI 1, 0x12 HDMI 2); 0x1B is shown as "USB-C" if the G3223D confirms it, else as hex (D3).

## What changed from the plan

- Transport retries went from three to five with a doubling pause (RR9).
- `MonitorStore` caches capabilities by serial across rediscovery; the plan's "parsed once per display" note assumed the display set only changes on plug and unplug. It also changes on every PiP or input switch.
- `monitorctl` ships inside the bundle and is linked into `/opt/homebrew/bin` by `--install`, so FR7's command line needs no separate install.
